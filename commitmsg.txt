Fix two startup crashes found by running the 0.1.0 installer

The shipped Windows build was executed for the first time and never showed a
window. Event Viewer showed two crashes in sequence; no milestone test caught
either because nothing constructed the real App/MainWindow.

1) CryptographicException at App.OnStartup: settings DeviceName (a bare machine
   name, DESKTOP-IHAMU4O) was passed as the certificate subject, but
   CertificateRequest requires an X.500 DN. CertificateProvider.ToDistinguishedName
   now normalizes at one choke point - DN strings pass through, bare names are
   emitted via X500DistinguishedNameBuilder. Hand-escaping was rejected after
   probing the parser: it accepts \< and \\ but rejects \, \+ \; \".

2) XamlParseException at new MainWindow(): MainWindow.xaml binds
   StaticResource BooleanToVisibilityConverter, which was never defined (only the
   inverse converter was registered). Extracted all shared brushes/styles/
   converters to App/Themes/AppResources.xaml, merged by App.xaml and by
   MainWindow.xaml so the window is self-contained.

Also fixed:
- StartupUri in App.xaml created a second top-level window next to the one
  App.OnStartup builds; the published exe showed two identical windows. Removed.
- StaRunner let exceptions escape the STA thread and tear down the whole test
  host (one XAML failure aborted the run). It now rethrows on the test thread
  via ExceptionDispatchInfo, preserving the stack.

Tests: +6 CertificateProviderTests, +2 MainWindowConstructionTests (157 total,
0 warnings). Negative control run: commenting the converter key out fails both
window tests with the original stack; restoring it passes them.

Verified on the real machine: published exe alive after 8s, port 48600
listening, exactly one window titled "Mac2Win Transfer - Receiver". Installer
rebuilt: win-receiver/installer/Output/Mac2WinReceiver-Setup-0.1.0.exe (59 MB).

docs/VERIFICATION.md gains a post-release defect table; ADR-019 records the
decision and the remaining honest gap (App.OnStartup wiring is a REAL-DEVICE
check - WPF allows one Application per AppDomain).
